# Markdown 笔记规范

先读完再动手。1 至 4 必线性，上一步产出是下一步输入。门禁不过不前进。不确定就停下问，禁止靠假设做完。

## 步骤

### 1. frontmatter

- 输入：已有笔记，或对话里已经说出的内容
- 动作：有文件先读完。无文件只收对话已出现的信息；缺落盘位置就停下问。按第 1 组补齐
- 产出：第 1 组
- 门禁：第 1 组未齐不继续。无文件不停。非 Markdown 则停下并说明该走哪条路径

### 2. 选结构

- 输入：第 1 组
- 动作：按第 2 组降级并做文档归位。检索只允许下述这三项，其余检索禁止。排版、空格、列表、加粗不查全库。一条格式规则无法判定时，只对照同文件夹下或`0 认知`中两篇 `tags` 为 `已阅` 的笔记；仍无法判定则停下问
	- 出链：当前笔记里每个双向链接的目标是否存在
	- 入链：全库搜索指向当前笔记、其标题和块 ID 的链接；改标题或块 ID 时同步改入链
	- 结论：用结论原句搜索；已有主文档则本篇改为引用
- 产出：第 2 组
- 门禁：结构已选定。未定稿不进入第 3 组

### 3. 落盘

- 输入：第 2 组
- 动作：按第 3 组写正文。材料只来自已有笔记或对话已说出的信息。只改格式，不改立场，不写没说过的内容，不加步骤外的工具或脚本
- 产出：第 3 组
- 门禁：未改范围外文件。写入一次

### 4. 核对

- 输入：第 3 组落盘后的正文
- 动作：按第 4 组逐条核对。不过则改正后再验一次，通过后停止
- 产出：正文
- 门禁：第 4 组全勾后，只交付正文

## 产出

同号对应步骤。每条都是硬约束。缺一栏就不交付。一条只判一件事，且只占一行。按逻辑先后排列。

### 1. frontmatter

示例：

```yaml
---
tags: [已阅, foo]
date: 2026-09-28
---
```

- [ ] 当前值为 `待审`（待人类审阅）、 `已阅`（人类已审阅）
- [ ] `date` 为最近更新日期
- [ ] 偏离示例时，结束前改回示例

### 2. 选结构

- [ ] 默认用最轻的格式，即段落和标题
- [ ] 能用文字不用列表，能用列表不用表格
- [ ] 单一事物 → 段落
- [ ] 逻辑承接 → 段落
- [ ] 超过两行 → 段落
- [ ] 名称-定义 → 列表或段落
- [ ] 两列且无对比 → 列表或段落
- [ ] 单元格是完整句 → 列表或段落

### 3. 落盘

**文件名**

- [ ] 不超过 15 个字符
- [ ] 见名知意，高度概括本文内容
- [ ] 英文标题用 sentence case

**标题**

- [ ] `#` 全文唯一
- [ ] 标题只用到 `###`
- [ ] ≤ 20 字
- [ ] 结尾无句号
- [ ] 见名知意，高度概括所属正文内容

**排版**

- [ ] 标题与正文间 1 个空行
- [ ] 章节间 1 个空行
- [ ] 正文 `---` 只用于重大划分，除 frontmatter 外全文不超过三处
- [ ] 字母、数字、计算符号左右各空 1 格；紧邻标点的一侧以及字母和数字间不空
- [ ] 段落间 1 个空行
- [ ] 两空格硬换行只用于同一段内要强制断行的正文行（相邻行之间无空行）
- [ ] 标题、列表项、表格行、代码块、分隔线、单行引用等块级行，行末不加两空格；它们本身就会换行
- [ ] 全文档末有 `\n`

**摘要**

- [ ] `#` 下 3 行内写摘要
- [ ] 写明本文是什么，做什么，什么时候读

**措辞**

- [ ] 简洁明确，实用直观
- [ ] 显式清晰，避免歧义
   - [ ] 同一概念只用一个名称
   - [ ] 具体名词替代抽象词
   - [ ] 代词指代唯一

**列表**

- [ ] 线性或并行关系需要摊开时才用列表
- [ ] 并列、不分先后、短小条目用 `-`
- [ ] `-` 条目一条一核心，且不过长
- [ ] 有明确顺序的步骤、操作流程、排名或优先级用 `1.`
- [ ] 编号交给渲染器
- [ ] 每个步骤完整表达
- [ ] 嵌套不得超过两级，一级缩进一个 tab

**表格**

- [ ] 表格仅用于多维度、需对比的数据
- [ ] 表头加粗
- [ ] 对齐用 `:--`、`:--:`、`--:`
- [ ] 单元格简洁、不过长

**代码**

- [ ] 代码块标注语言
- [ ] 行内代码用反引号

**引用**

- [ ] `>` 用于重要提示或引用内容
- [ ] 多行引用且行间无空行、又要强制断行时，才在行末加两空格；单行引用不加
- [ ] 不得作为正文的替代格式

**加粗**

- [ ] 用于首次定义关键术语，或强调重要操作或警告
- [ ] 不得只为引导注意而加粗
- [ ] 不得给普通名词加粗
- [ ] 不得给所有术语名词加粗
- [ ] 不得连续加粗

**链接**

- [ ] 外链用 `[文本](url)`
- [ ] 库内用相对路径
- [ ] 只链直接相关的下一层，不链间接文档
- [ ] Obsidian 双向链接，主文档留稳态结论，操作文档引用该结论，确保改一处则引用处一起生效
- [ ] 不存在失效的 Obsidian 双向链接
- [ ] Obsidian 双向链接角标位于文本末尾，不换行

**引号**

- [ ] 直接引用用引号
- [ ] 首次定义术语用引号
- [ ] 特殊含义用引号
- [ ] 界面元素名称用引号
- [ ] 英文引号用 `"`
- [ ] 中文引号用 `「」`
- [ ] 不得给普通名词加引号
- [ ] 不得在标题里频繁使用引号
- [ ] 不得在列表项里频繁使用引号
- [ ] 整句引用改用引用块

### 4. 核对

- [ ] 任一条不过就先改完
- [ ] 不写规格未要求的解释
- [ ] 不写规格未要求的替代方案
- [ ] 不靠范围外的改动收尾
- [ ] 上面都通过才交付正文
