# AGENTS.md 撰写

先读完本文件再动手。必填节直接生成，选填节先问用户，无法确认的留占位不猜。

## 流程

1. 通读项目全部文件，判断项目类型：代码 / 文档 / 混合（混合项目按子项目分别判断哪些节适用）
2. 按模板逐节写；标「代码项目」的节在文档项目跳过，选填节先问用户本节有无必要
3. 对照验收清单自检落盘

## 模板

```markdown
## 相关文档（必填）

入口链接，用相对路径。

- [README.md](./README.md)：人类阅读入口

## 项目概述（必填）

三行内说清项目是什么、放什么、给谁用。示例如下：

量潮实训基地的领域级第二大脑，存放规章、任务清单与工程规范，承接基地成员的多人异步协作。

## 快速定位（选填）

若生成，列从用户话里到文件的映射，三列：

| **关键词** | **文件** | **锚点** |
| :--- | :--- | :--- |
| 协作流程 | [co-guide.md](./docs/handbook/co-guide.md) | 发布任务 |
| 命名规范 | [second-brain.md](./docs/specification/second-brain.md) | 规则总览 |

## 业务意图（代码项目必填）

三行内说清为什么做，即要解决的痛点。示例如下：

把商务邮件与群聊里的流程状态抽成结构化数据，供工作台直接查询。

## 关键决策（代码项目必填）

有序列表，不超过 5 条，每条一句话。

1. 状态枚举以 handbook 的 E1-E18 为准，不自造字段

## 管道逻辑（代码项目选填）

若生成，用 mermaid 概括核心模块与数据流向，不展开细节。

flowchart LR
    A[邮件与群聊原文] --> B[抽取器] --> C[(状态库)]

## 技术栈（代码项目选填）

若生成，不超过 5 个，精确到主版本号。

- Python 3.13、SQLite 3.45

## 项目目录（必填）

简单树，不全部展开，只列关键文件和文件夹并标注职能。

## 常用命令（选填）

若生成，不超过 5 条，每条标注用途。

- `pytest`：跑测试
- `ruff check`：静态检查

## 核心原则（必填）

只放影响 AI 行为的刚性规则：缺了会做错、或必须遵守。下面 5 条固定保留，可按项目扩展，不超过 10 条。

- 最小干预：仅在用户明确请求时改文件，不主动改无关文件
- 用到再建：除本文列出的路径和 README、AGENTS.md 这类根契约外，不创建未使用的文件或目录
- 结构同步：改名或变更目录后，README、本文对应内容与内部链接必须同一轮改完
- 最大兼容：优先 GFM / CommonMark，不用编辑器私有语法
- 信息复用：不把其他文件正文抄进本文，用相对链接

## 工作流程（必填）

有序列表，每步一句话，尽量短。

1. 明确请求范围，只改被要求的文件
2. 执行操作；工具放 `.agent/skills/{工具短名}/`
3. 目录有变更时，同一轮同步 README 与本文
4. 对照验证清单逐项核对

## 常见任务（选填）

项目有高频重复操作才写，一次性或偶发的不写。

### 日常改动

1. 同步 main，开新分支
2. 改完自检，提交并推分支

## 安全约束（必填）

下面 1 条固定保留，可按项目扩展，不超过 5 条。

- 禁止把密钥、口令、令牌写进仓库文件或协作材料（设计、截图、视频、任务页）

## 验证清单（必填）

复选框，覆盖关键产出物，全部通过才算完成。

- [ ] 只改了用户明确请求的文件
- [ ] 未创建未使用的文件或目录
- [ ] 新增或改名路径已确认落点
- [ ] 项目目录为简单树，关键文件与文件夹已标注职能
- [ ] 核心原则只放刚性规则，无示例残留
- [ ] 工作流程每步一句话，无冗余
- [ ] README 与本文目录、内部链接已同一轮同步
- [ ] 无法确认的条目已留占位，未猜测填写
```

## 验收清单

落盘后逐条核对，全部通过才交付。

- [ ] 项目类型已判断；文档项目未写业务意图、关键决策、管道逻辑、技术栈
- [ ] 必填节齐全，选填节已逐节问询用户
- [ ] 选填节未生成时已整节删除，产物中不留空标题
- [ ] 核心原则含固定 5 条，扩展后不超过 10 条
- [ ] 安全约束含密钥禁令，不超过 5 条
- [ ] 内部链接指向已存在的文件
- [ ] 全文小于 150 行
