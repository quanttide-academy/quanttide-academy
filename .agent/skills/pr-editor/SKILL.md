# PR 编辑

## 流程

1. 读分支相对默认分支的全部 commit 与改动文件
2. 归纳出一条主干改动，写标题：一句话、60 字符内、不加句号；只有 1 个 commit 取其 subject，多个 commit 归纳一条，跨多个不相关领域按主要改动定性
3. 按模板逐段写描述，有关联任务才补「关联问题」
4. 对照验收清单自检后提交

## 模板

```markdown

## 摘要

2-3 句说清改了什么、为什么改，不写实现细节。

## 改动

按领域分组列出关键改动，文件多时分组，不无序平铺。

## 验证

写可复现的命令或步骤；没有自动化测试就写手工验证步骤。

## 关联问题

仅有任务或 Issue 时写，没有就不写这段。

```

## 验收清单

- [ ] 标题与 commit 对得上，未超出 commit 范围
- [ ] 标题为一句话、60 字符内、无句号
- [ ] 摘要 2-3 句，未写实现细节
- [ ] 改动按领域分组，未无序平铺
- [ ] 验证写了可复现的命令或步骤
- [ ] 关联问题仅在有关联任务或 Issue 时写入
- [ ] 未编造 commit 里没有的改动
- [ ] 标题与正文段落之间留空行
- [ ] 全文小于 150 行
