# PR 撰写

从 commit 出发写标题和描述，不编造 commit 里没有的改动。仓库另有 PR 规范时，以仓库规范为准。

## 流程

1. 读分支相对默认分支的全部 commit 和改动文件
2. 归纳出一条主干改动，写标题
3. 按三段写描述；有关联任务时补一段
4. 对照提交前自检逐条核对

## 标题

- 一句话说清这个 PR 做了什么，60 字符内，不加句号
- 分支只有 1 个 commit 时用它的 subject；多个 commit 时归纳一条
- 改动跨多个不相关领域时，按主要改动定性，不堆砌

示例：

- 新增 agents-editor 与 pr-editor 两个 skill
- 修复日卡日期与星期错位

## 描述

### 摘要

2-3 句说清改了什么、为什么改，不写实现细节。

### 改动

按领域分组列出关键改动；文件多时分组，不无序平铺。

### 验证

写清怎么验的：跑什么命令、看什么结果；没有自动测试就写手工验证步骤。

### 关联问题

关联了任务或 Issue 才写，格式随仓库约定；没有就不写这段。

## 提交前自检

- [ ] 标题与 commit 对得上，未超出 commit 范围
- [ ] 标题一句话、60 字符内、无句号
- [ ] 摘要 2-3 句，未写实现细节
- [ ] 改动按领域分组，未无序平铺
- [ ] 验证写了可复现的命令或步骤
- [ ] 未编造 commit 里没有的改动
- [ ] 标题与正文段落之间留空行
