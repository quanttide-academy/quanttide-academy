# Markdown 笔记规范

按本规范撰写、编辑、重命名 Markdown 笔记。允许将本规范全文作为提示词提供给 AI，要求其按照本规范输出格式。AI 是格式执行工具而非决策者。

## 执行顺序

1. 写前检查 frontmatter：缺 `tags` / `date` 或结构不一致，补齐前不继续
2. 选结构：按降级链选型，能简单就不用更重的格式
3. 按结构 / 块级 / 行内落盘
4. 提交前校验：任一项失败必须改完再交；提交前检查并清除 AI 常见的格式过度

## 选结构

格式元素：组织或装饰文档内容的 Markdown 语法，含标题、列表、表格、分隔线、代码块、块引用、加粗、链接。

格式过度：同一文档中不必要地使用过多格式元素类型或频次，加重视觉负担而非提升清晰度。

降级链：段落和标题 → 列表 → 表格。优先使用段落和标题组织内容；能用文字不用列表，能用列表不用表格。删不必要格式，全文格式元素压到必要最小。同一概念全程使用相同名称，不得混用不同术语指代同一事物。

命中即降一级：

- 单一事物、逻辑承接、超过两行 → 用段落，不用列表
- 名称-定义对应、两列且无对比、单元格是完整句 → 不用表格
- 章节间隔 → 空行加标题，不用分隔线

## frontmatter（强制）

创建/编辑/重命名笔记时，**必须立即检查 frontmatter**。写完对照下方范例，**结构必须一致**，不一致则重写后再继续。

- 缺少 `tags` 或 `date` 时**必须补充，不补充不继续**
- `date` 取值：最近一次更新日期，格式 `YYYY-MM-DD`，单独一行
- `tags` 取值只能是 `待审`（待人类审阅）或 `已阅`（人类已审阅）；允许多个，仍写在同一行方括号内

格式范例（唯一合法结构）：

```yaml
---
tags: [已阅]
date: 2026-05-14
---
```

多标签只改方括号内部，逗号后一空格：`tags: [已阅, foo]`

校验（全部通过才算完成）：

- `---` 后第一行必须以 `tags: [` 开头、以 `]` 结尾
- 第二行必须是 `date: YYYY-MM-DD`
- 第三行必须是 `---`

禁止（出现即失败，必须改回范例）：

- YAML 块列表：`tags:` 换行后再写 `- 已阅`
- 无方括号：`tags: 已阅`
- 键值拆到多行、或在 `tags`/`date` 之间插入空行或其他字段
- 依赖 Obsidian `property:set` 的默认输出：若 CLI 写成块列表，结束前必须改回本范例

## 结构

### 标题

默认：

- `#` 仅文档主标题，全文唯一，不得出现第二个一级标题
- `##` → `###`，最多 3 级，不得更深
- 标题与正文之间、章节之间各 1 个空行
- ≤ 12 字，3 秒内能读完；见名知意，简洁明确概括章节内容，快速匹配查询需求
- 无标点；中文标题用中文；英文标题用句子大小写（Sentence case），仅首字母大写（专有名词除外）

失败：出现 `####`；出现第二个 `#`；标题含标点；标题与正文之间无空行

### 分隔线

默认：优先空行加标题区分章节。正文 `---` 仅用于重大划分节点，全文不超过三处。可用于文档顶部元信息与正文之间，不得在每个章节间重复。frontmatter 的 `---` 不计入正文分隔线。

禁止：作为视觉装饰或填充；用分隔线代替章节标题。

失败：正文 `---` 超过三处；每个章节间都有分隔线

## 块级

### 文本

默认：

- 简洁明确，实用直观
- 段落末须 2 个空格；段落间 1 个空行；最后一行末尾换行（`\n`）
- 没有歧义和模糊表述：代词指代唯一，具体名词替代抽象词
- 字母、数字、计算符号左右空 1 格

禁止：使用「非常」「简单的」「显而易见的」等冗余修饰词。

失败：段末缺两空格；文末无 `\n`；出现上述冗余修饰

### 列表

默认：

- 并列、不分先后、短小条目用 `-`；一条一核心信息且不过长
- 有明确顺序的步骤、需要编号的操作流程、排名或优先级用 `1.`；渲染器自动生成连续编号；每个步骤完整表达
- 嵌套不得超过两级，缩进使用两个空格
- 短条目用分号结尾；独立完整句才用句号；一篇只许一种

禁止：描述单一事物、内容有逻辑承接、超过两行仍用列表。

失败：超两行仍是列表；嵌套超两级；同一篇分号与完整句混用；缩进用 tab

### 表格

默认：仅用于呈现多维度、需对比的数据。表头加粗，对齐用冒号（`:--` `:--:` `--:`）。单元格简洁、不过长。

禁止：仅为名称-定义对应（改用列表）；两列且无对比需求；单元格内容需用完整句子表达。

失败：对无对比的两列或名称-定义用了表格；单元格写成完整句

### 代码

默认：代码块必须标注语言类型，以便语法高亮。行内代码使用反引号包裹，如 `variable`、`function()`、`file.md`。

失败：代码块无语言标记

### 引用块

默认：块引用（`>`）用于标注重要提示或引用内容。行末加 2 个空格。

禁止：作为正文的替代格式。

失败：大段正文写在 `>` 里

## 行内

### 加粗

默认：仅用于首次定义关键术语、强调重要操作或警告。引导注意力到关键信息不得单独作为加粗理由，须同时属于上述两类。

禁止：对普通名词或所有术语名词加粗；连续多个加粗；在列表项内部加粗。

失败：列表内出现加粗；连续加粗；普通名词加粗

### 链接

默认：

- 外部：`[链接文本](https://example.com)`
- 内部相对路径：`[文档](./docs/guide.md)`
- 一层浅索引：只链直接相关的下一层，不链间接文档，一段内不堆相关链接

失败：内部链接不用相对路径；一段内堆多条间接链接

### 引号

默认：用于直接引用他人话语、首次定义术语时标记、强调词汇的特殊含义、标注界面元素名称。英文用 `"`，中文用 `「」`。

禁止：对普通名词加引号；在列表项或标题中频繁使用；包裹整个句子作为引用（改用块引用）。

失败：标题或列表项里频繁引号；整句用引号代替引用块

## 提交前校验

全部通过才算完成。任一项失败必须改完再交。清除 AI 常见的格式过度。AI 与人的可读性良好。

- [ ] frontmatter 为三行范例结构：`tags: [...]`、`date: YYYY-MM-DD`、`---`
- [ ] `#` 只出现一次，无 `####`
- [ ] 正文分隔线不超过三处；未用分隔线装饰章节间隔
- [ ] 未出现「非常」「简单的」「显而易见的」
- [ ] 未把任何内容都做成列表或表格
- [ ] 无连续加粗、列表内加粗、普通名词加粗
- [ ] 代码块均有语言标记
- [ ] 列表未超两行、未超两级、全文结尾风格一致
- [ ] 引用块未替代正文
- [ ] 文末有 `\n`，段落末有两空格
